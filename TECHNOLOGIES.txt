TECHNOLOGIES / PLATFORM SPECIFICATIONS
Last Updated: 2026-04-02 | v4.3.0
======================================

1. FRONT END
   Runtime / Framework
   - React 19                    Core UI library (JSX, hooks, lazy/Suspense code splitting)
   - React Router DOM 6          Client-side routing with protected routes

   UI & Styling
   - Material-UI (MUI) 7         Component library, theming, and icon set
   - Tailwind CSS 3              Utility-first styling (glassmorphism, gradients)
   - Framer Motion               Micro-animations and page transitions

   Data & Charts
   - Recharts 3                  Composable bar, line, pie, and area charts
   - React Grid Layout 2         Draggable and resizable dashboard widget grid

   State & Data Fetching
   - React Context API           Auth state and global preferences
   - Axios                       HTTP client with request/response interceptors
                                 (auto-attaches JWT Bearer token; handles 401 via
                                  custom event dispatch for SPA-safe redirects)

   Notifications & UX
   - React Hot Toast 2           Lightweight toast notification system
   - Zod (shared contracts)      Input validation schemas mirroring backend

   Performance
   - React.lazy + Suspense       Route-level code splitting
   - useCallback / useMemo       Memoisation of expensive computations
   - AbortController             Cancels in-flight API requests on unmount
   - LRU memoize cache           Capped at 100 entries to prevent memory leaks

   Storage
   - localStorage                Dashboard layout persistence, auth token storage
                                 (JSON.parse wrapped in try/catch — crash-safe)
   - sessionStorage              Short-lived session data


2. BACK END
   Runtime & Framework
   - Node.js (v16+)              Server runtime
   - Express 4                   HTTP framework (REST API)
   - nodemon 3                   Auto-reload in development
   - node-cron 3                 Scheduled intelligence synchronization

   Authentication & Security
   - jsonwebtoken 9              JWT generation (24 h expiry) and verification
   - bcryptjs 2                  Password hashing (salt rounds: 10)
   - Helmet 7                    HTTP security headers (XSS, HSTS, etc.)
   - CORS 2                      Origin-locked — reads CLIENT_ORIGIN from .env
   - Zod 3                       Request body validation on all POST/PATCH routes

   Threat Intelligence & SOAR
   - OpenCTI (Support)           GraphQL integration for external threat feeds
   - NAXSI (Firewall)            WAF policy generation and automated reloading
   - Audit Logger                Internal action tracking and compliance metrics

   Database & ORM
   - PostgreSQL (v13+)           Primary relational database
   - Prisma ORM 5                Schema definition, migrations, and typed queries
                                 (Singleton PrismaClient reused across hot-reloads)

   Logging & Monitoring
   - Morgan 1                    HTTP request logging (dev format)
   - console.error               Contextual error logging in all controllers

   Reliability (v4.2.0)
   - Post-Deployment Verify      Automated verification of firewall rule status
   - RBAC Middleware             Fined-grained permission control (Admin/Analyst)
   - JWT_SECRET startup guard    Server exits (process.exit 1) if secret is missing
   - Prisma P2025 handling       PATCH /alerts/:id returns 404 (not 500) on missing record
   - Graceful shutdown           SIGTERM / SIGINT close HTTP server and disconnect Prisma

   API Endpoints
   POST   /api/auth/register     Create analyst account (public)
   POST   /api/auth/login        Returns JWT (public)
   GET    /api/auth/profile      Authenticated user profile (private)
   GET    /api/alerts            All alerts, ordered by timestamp (private)
   POST   /api/alerts            Create alert (admin only)
   GET    /api/alerts/stats      Aggregate stats (total, critical, open cases, IOCs)
   PATCH  /api/alerts/:id        Update alert status (private)
   GET    /api/intel/threat-actors  All threat actors (synchronized from OpenCTI)
   GET    /api/intel/iocs           All Indicators (synchronized from OpenCTI)
   POST   /api/rules/deploy         Deploy production rules to NAXSI (Admin)
   POST   /api/rules/:id/approve    Approve protection rule (Admin)
   GET    /api/incidents            Manageable cases and threat timeline (private)


3. ENVIRONMENT VARIABLES
   Server (.env)
   - PORT                        Server port (default: 5000)
   - DATABASE_URL                PostgreSQL connection string (required)
   - JWT_SECRET                  Token signing secret (required)
   - NAXSI_RULES_PATH            Path to production configuration file
   - OPENCTI_TOKEN               API key for intelligence synchronization

   Client (.env)
   - REACT_APP_API_URL           Backend base URL (default: http://localhost:5000)


4. HARDWARE / DEPLOYMENT
   Requirements
   - Linux VM (Ubuntu Recommended) for NAXSI/Nginx firewall integration
   - Node.js v16+, PostgreSQL v13+
   - Client Requirements: Modern web browser (Chrome 90+, Firefox 90+)
